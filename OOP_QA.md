# Ответы на вопросы по ООП в C++

## Что такое виртуальный класс

В стандарте C++ нет отдельного термина «виртуальный класс». Обычно под ним
имеют в виду одну из трёх вещей.

### Класс с виртуальными функциями

Виртуальная функция допускает переопределение в наследнике и позднее
связывание:

```cpp
class Task {
public:
    virtual ~Task() = default;
    virtual void complete(const DateTime& now) = 0;
};
```

Если есть `Task& task`, выражение `task.complete(now)` вызовет реализацию
реального объекта: `DeadlineTask`, `RecurringTask` или `ChecklistTask`.

### Абстрактный класс

Класс абстрактен, если у него остаётся хотя бы одна чисто виртуальная функция,
объявленная с `= 0`:

```cpp
class Report {
public:
    virtual ~Report() = default;
    virtual ReportResult<ReportRow> generate(
        const ApplicationState& state,
        const DateTime& now
    ) const = 0;
};
```

Создать `Report report;` нельзя. Можно создать наследника и работать через
ссылку или указатель на `Report`.

### Виртуальный базовый класс

Это другое средство, связанное с ромбовидным наследованием:

```cpp
class Person {};
class Student : virtual public Person {};
class Employee : virtual public Person {};
class TeachingAssistant : public Student, public Employee {};
```

`virtual public Person` гарантирует, что в `TeachingAssistant` будет одна
общая базовая часть `Person`, а не две. В Deadline Planner ромбовидного
наследования нет, поэтому виртуальные базовые классы не нужны.

## Как использовать абстрактный класс в C++

1. Объявить общий публичный контракт.
2. Добавить виртуальный деструктор.
3. Сделать хотя бы один метод чисто виртуальным.
4. Создать наследника и переопределить методы с `override`.
5. Работать через ссылку или умный указатель на базу.

```cpp
std::vector<std::unique_ptr<Task>> tasks;
tasks.push_back(std::make_unique<DeadlineTask>(data));
tasks.push_back(std::make_unique<RecurringTask>(data, 7));

for (auto& task : tasks) {
    task->complete(now);
}
```

Почему деструктор виртуальный:

```cpp
virtual ~Task() = default;
```

Объект наследника удаляется через `std::unique_ptr<Task>`. Без виртуального
деструктора удаление через базовый указатель приводит к неопределённому
поведению и может не освободить ресурсы наследника.

## Что делают `override` и `final`

`override` просит компилятор проверить, что метод действительно переопределяет
виртуальный метод базы:

```cpp
void complete(const DateTime& now) override;
```

Если сигнатура ошибочна, код не скомпилируется.

`final` запрещает дальнейшее наследование или переопределение:

```cpp
class DeadlineTask final : public Task {};
```

В проекте конкретные типы помечены `final`, потому что их контракты завершены,
а расширяться должна иерархия через новый класс-наследник `Task`.

## Чем абстрактные классы C++ отличаются от Python

### C++

- Абстрактность является частью языка.
- Чистая виртуальная функция записывается `= 0`.
- Проверка выполняется во время компиляции.
- Для безопасного удаления через базу нужен виртуальный деструктор.
- Полиморфное владение обычно выражают `std::unique_ptr<Base>`.
- Сигнатуры и типы проверяются статически.

### Python

Обычно применяют `ABC` и `@abstractmethod`:

```python
from abc import ABC, abstractmethod

class Task(ABC):
    @abstractmethod
    def complete(self, now):
        pass
```

- Абстрактность поддерживается модулем `abc` во время выполнения.
- Нет ручной модели удаления и виртуального деструктора.
- Тип объекта определяется динамически.
- Часто можно использовать duck typing без общего базового класса.
- Аннотации типов обычно не влияют на выполнение программы.

Короткий ответ преподавателю:

> В C++ абстрактный класс задаёт compile-time контракт через чистые
> виртуальные функции, а вызов через базовую ссылку использует динамический
> полиморфизм. В Python похожий контракт делают `ABC` и `@abstractmethod`, но
> он проверяется во время выполнения, и виртуальный деструктор не нужен из-за
> другой модели управления памятью.

## Можно ли реализовать чисто виртуальную функцию

Да, у чисто виртуальной функции может существовать определение, хотя класс
всё равно остаётся абстрактным. Наследник обязан предоставить override, а
реализацию базы можно вызвать явно. Это редкий приём; в проекте он не нужен.

Чисто виртуальный деструктор тоже обязан иметь определение:

```cpp
class Base {
public:
    virtual ~Base() = 0;
};

Base::~Base() = default;
```

В проекте используется более простой вариант `virtual ~Base() = default`.

## Что такое таблица виртуальных функций

Стандарт не требует конкретной реализации, но компиляторы обычно создают
vtable — таблицу адресов виртуальных методов. Объект полиморфного класса хранит
скрытую ссылку на таблицу своего реального типа. Через неё программа выбирает
нужную реализацию во время выполнения.

Говорить, что vtable обязательна по стандарту, не следует. Это типичная
реализация механизма, а не формальное требование языка.

## Почему в проекте несколько абстрактных классов

Каждый описывает отдельную точку изменения:

- `Task` — разные правила поведения задачи;
- `TaskRepository` — разные способы хранения;
- `Report` — разные алгоритмы агрегации;
- `ReminderRule` — разные условия напоминания;
- `StateExporter` — разные форматы представления.

Абстракции не созданы ради числа классов. У каждой есть минимум два или три
реальных наследника и место, где они используются полиморфно.

## Частые дополнительные вопросы

**Чем перегрузка отличается от переопределения?**

Перегрузка — одинаковое имя и разные параметры, выбор обычно при компиляции.
Переопределение — наследник заменяет виртуальную реализацию с той же
сигнатурой, выбор происходит по реальному типу объекта.

**Чем указатель отличается от ссылки?**

Ссылка должна быть связана с объектом и обычно не бывает пустой. Указатель
может быть `nullptr` и переназначаться. Для владения проект использует умные
указатели, для невладеющего обязательного доступа — ссылки.

**Зачем `const`?**

Он выражает запрет изменения через данный интерфейс. Например, отчёт получает
`const ApplicationState&`, потому что только читает состояние.

**Что такое RAII?**

Ресурс захватывается конструктором объекта и освобождается деструктором. Так
работают `unique_ptr`, файловые потоки и окна, для которых проект хранит
дескрипторы в объекте интерфейса.

**Что такое сильная гарантия исключений?**

Если операция завершается исключением, наблюдаемое состояние остаётся таким,
каким было до вызова. `TaskService::commit` достигает этого работой с копией и
публикацией только после успешного `repository.save`.
